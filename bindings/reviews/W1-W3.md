# W1–W3 checkpoint review, 2026-10-30

Review scope: strict Java request boundary, WebCrypto provider/default-RNG guard, lazy worker
runtime, ordinary hash/Pedersen/BBS adapters. This is an implementation self-review, not an
independent cryptographic audit or approval of secret operations in browsers.

## Findings addressed during implementation

- A Node/browser worker file initially used import.meta in its Node branch, which is still
  invalid syntax in a classic browser worker. Removed it; actual Chromium/Firefox runs pass.
- Image integrity previously risked a second file read after the checked bytes. The patched
  launcher consumes the exact checked Uint8Array; both patch anchors are asserted.
- G1Pedersen's provider capability probe invokes a secret multiplication. Public verification
  now selects a public-only delegating provider through the existing provider interface, so
  checking a disclosed opening does not require entropy. Generation still uses pure Java's
  secret path. An absent-entropy image test covers the distinction.
- Opaque JS handles are checked in a runtime-owned WeakMap and against their physical image.
  A handle from another runtime cannot alias an identically numbered Java handle.
- Request queue bounds now include calls waiting for startup. Disposal rejects pending calls
  and waits for Node worker termination. Failed images never automatically replay operations.
- Browser asset loading is bounded by the expected pinned length while streaming.
- BBS secret-key import explicitly rejects zero. Disclosure indexes must be ordered and unique.
- JVM construction sites using SecureRandom method references (BLS/Jubjub blinding) were
  included in the default-RNG guard, not only literal constructor expressions.

## Measured evidence so far

- Java boundary/hash adapter tests: 5 passed.
- Existing Java regressions: zeroj-api 122, zeroj-bbs 89, selected zeroj-bls12381 tests 138;
  no failures/errors/skips in those runs.
- Node 22.12.0 with experimental-wasm-exnref: 44 independent Pedersen scalar/byte commitment
  vectors across BLS12-381/Jubjub; 50 official CFRG BBS signature/presentation fixtures across
  SHA-256/SHAKE-256; fresh randomized presentations, challenge tampering, foreign/released
  handles, strict hash inputs, concurrent calls, duplicate providers and modified Wasm.
- Actual Web Image without the provider rejects default RNG, BBS creation and G1 Pedersen
  generation, with zero observed Math.random calls. Separate probes cover missing/throwing
  entropy, late failure, 65,536-byte chunks, and public verification without entropy.
- Chromium 156.0.8078.4 and Firefox 157.0: typed hash example passes, no eager image request,
  one image load across repeat calls, no page errors, no horizontal overflow at 390px.
- npm dependency audit at install: zero reported vulnerabilities.

Tests of this checkpoint do not cover the unfinished Groth16/confidential adapters.
Full browser capability parity, npm packed-consumer tests, distribution notices and final
release review remain W4–W6 work. No Safari/constant-time/zeroization/production claim follows.
