# Groth16/BLS12-381 independent evidence (#47)

This is reproducible release evidence under accepted ADR-0025 decisions 2/6 and
ADR-0026. It does not change maturity claims or replace independent cryptographic
review. All scalars and witnesses below are public test data. Random seeds are
fixed to make failures reproducible; they are not production entropy sources.

## Standing CI coverage

The default `./gradlew build -PskipSigning=true` and platform `test` jobs run these
ordinary JUnit tests. No Node installation is needed to consume the committed KAT.

| Test | Independent evidence and boundary |
| --- | --- |
| `ExternalPairingKatTest` | All 12 generator-pairing Fp12 coefficients from locked ffjavascript 0.3.1; no ZeroJ output is used to generate the fixture. |
| `BlstBls12381ProviderTest.seededPairingProductsMatchIndependentNativeOracle` | Twelve deterministic random three-pair products, each with a valid algebraic cancellation and a one-generator perturbation that both implementations must reject. Points are generated by the independently implemented JNI provider, pinned to `foundation.icon:blst-java:0.3.2`. |
| `G2MsmOracleTest` | Bucket MSM versus separate affine BigInteger double-and-add, across window thresholds, repeated points, infinity, zero, cancellation, negative scalars, r-1/r/r+1 and bit 254. This is an independent algorithm in the same repository, not an external library. |
| `Groth16CosetOracleTest` | Direct BigInteger Lagrange interpolation with no ZeroJ FFT/field helper. Checks every result for 7/8/9-row circuits and five separated coset positions for 4095/4096/4097 rows (domains through 8192), for both list and packed-CSR paths. Undersized domains must reject. |
| `Groth16DomainBoundaryTest` | 7/8/9-constraint multiplier circuits choose domains 8/8/16, generate proofs accepted by both verifiers, and reject a changed public input. |
| `Groth16AdversarialEnvelopeParityTest` | Raw envelopes traverse both complete verifiers. Every proof/VK/IC point position is tested with off-curve, on-curve out-of-subgroup, infinity, noncanonical field and malformed coordinate vectors. VK hashes are recomputed so rejection tests the point boundary, not a stale hash. |

The envelope test exposed a blst-java deserialization exception that was classified
as `INTERNAL_ERROR`, while the Java provider returned `INVALID_PROOF`. The fix
translates `RuntimeException` only around each native point constructor into the
existing malformed-input exception path. Validation and accepted points do not
change. This implements ADR-0025's typed-failure contract; it does not catch JVM
errors or turn unrelated pairing exceptions into invalid-proof results.

The `G2` JSON projective-policy decision remains #51; this test does not decide
whether a valid non-affine point should be accepted. Streaming-key mutations,
source pinning and bundle tamper tests are in the separate #48 implementation PR.
Existing heap/mmap and provider proof differentials remain in their normal suites.

## External pairing vector reproduction

From the repository root:

```sh
npm ci --ignore-scripts --prefix zeroj-test-vectors/tools/pairing-kat
node zeroj-test-vectors/tools/pairing-kat/generate.mjs > /tmp/zeroj-pairing-kat.txt
cmp /tmp/zeroj-pairing-kat.txt zeroj-test-vectors/src/main/resources/test-vectors/pairing-bls12381/ffjavascript-0.3.1-generator.txt
```

`package-lock.json` pins the complete dependency graph and npm integrity hashes,
including ffjavascript 0.3.1 and wasmcurves 0.2.2. The script pairs the package's
standard G1/G2 generators, then writes twelve canonical decimal field components,
one per line, in tower order `[Fp12.c0,c1][Fp6.c0,c1,c2][Fp2.c0,c1]`.

ADR-0047 documents the pairing convention difference: ffjavascript's result is
ZeroJ's reduced pairing cubed. The test compares **all twelve coefficients of
that cube**, and also rejects equality to the uncubed result. This reconciles the
specified convention without changing the primitive or replacing the independent
expected vector. Cubing is bijective in the prime-order target group here.

Pinned source references:

- [ffjavascript v0.3.1 pairing engine](https://github.com/iden3/ffjavascript/blob/v0.3.1/src/engine_pairing.js)
- [ffjavascript v0.3.1 root derivation](https://github.com/iden3/ffjavascript/blob/v0.3.1/src/f1field.js): first quadratic nonresidue, yielding 5 for this scalar field.
- [snarkjs v0.7.6 Groth16 prover](https://github.com/iden3/snarkjs/blob/v0.7.6/src/groth16_prove.js): coset numerator representation; the H-query basis absorbs division by the vanishing polynomial.

The interpolation oracle independently derives the root and evaluates
`L_j(x) = (x^n - 1) * omega^j / (n * (x - omega^j))`, then compares
`A(x)B(x)-C(x)` to the prover's H-query scalars. Large-domain checks sample five
outputs; this is not exhaustive large-domain verification or a scale benchmark.

Run the focused evidence suite:

```sh
./gradlew :zeroj-crypto:test --tests '*G2MsmOracleTest' --tests '*Groth16CosetOracleTest' --tests '*Groth16DomainBoundaryTest' --tests '*ExternalPairingKatTest' :zeroj-blst:test :zeroj-verifier-groth16:test
```

Dependency upgrades require an explicit review, rerunning these commands on both
CI platforms, and documenting any vector/convention change. Do not update expected
coefficients merely to make a failing implementation pass. The pinned JNI build is
an oracle dependency, not a claim that all native versions have identical assurance.

## Remaining release gates

#47 remains an umbrella until the separate streaming mutation coverage and #51
profile choice are merged and all relevant CI lanes pass. Native-image, FFM MSM,
WASM, real-node E2E, malicious ceremony consistency and production-scale runs are
not newly certified by these tests. The existing assurance lanes and ADR-0026
external audit gates still apply.
