Hide a number (Pedersen commitments)

View Markdown ↗

Use this when a number has to live on a public ledger but stay private: a balance, a salary, a customer’s deposit. People can still check facts about it (“at least 1,000”, “inputs equal outputs”) and add many of them up, without ever seeing one.

A Pedersen commitment is a sealed envelope: a 32-byte curve point made from the value and a random blinding. It hides the value completely, it can’t be reopened as a different value, and commitments add up. A Groth16 proof can show facts about the hidden value.

Who learns what

Section titled “Who learns what”
PartyLearns
The committerThe value and its blinding (the opening)
A verifier given a proofOnly the proven fact, such as “at least 1,000”
Someone given the openingThe value; they can check it matches the commitment
Everyone elseA 32-byte commitment that reveals nothing

Real-world uses

Section titled “Real-world uses”
  • Proof of solvency. An exchange commits to every customer balance, proves the hidden total is covered by locked reserves, and each customer checks their own entry. (use case)
  • Confidential balances and transfers. Loyalty points or tokens move between holders, and a proof shows inputs equal outputs, with no amounts on the ledger. (use case)
  • Commit now, reveal later. Lock in a prediction, a price quote or a design hash today; open it after the deadline, and nobody can claim you changed it.
  • Committed credentials. A bureau commits to a credit profile; the holder proves “income ≥ 50,000” from it. (Prove a rule)
  • Product passports. An auditor commits to each measurement; the manufacturer proves “carbon ≤ 50 kg” without revealing it. (use case)

When not to use it

Section titled “When not to use it”
  • Someone else has to read the value without the owner’s help. A commitment opens only with the opening. Add chosen readers or encrypt for an auditor.
  • The value is a one-off answer. If nothing is stored on-chain, a plain predicate is simpler.

Watch out for

Section titled “Watch out for”
  • Sums wrap around. Commitment arithmetic is modulo a 252-bit number, so an unchecked sum can hide a “negative” amount. Prove every value’s range, and use ZkPedersen.assertBalanced, which refuses layouts that could wrap.
  • The blinding must be fresh, random and 252 bits. ZeroJ refuses circuits whose blinding is narrower, public or constant, but it can’t check that yours is random.
  • Create commitments offline. commit and randomBlinding run variable-time arithmetic on secrets; keep them on the user’s device or in an isolated process.
  • Decode received commitments with PedersenCommitment.decode, which checks the point is in the right subgroup.
  • Maturity. In-circuit commitments are ready, pending external review; sums and vector commitments are experimental.
