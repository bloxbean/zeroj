Encrypt for an auditor (ElGamal + proof)

View Markdown ↗

Use this when an authority must be able to read a value, and the sender must not be able to lie about it: a tax authority reading salaries, an auctioneer reading bids, a regulator reading transfer amounts.

The sender encrypts the value to the auditor’s public key with exponential ElGamal, and a Groth16 proof shows the ciphertext holds the same value as the public commitment (or satisfies a rule, such as “a bid between the reserve and the deposit”). A validator checks the proof, so a transaction with a fake auditor copy never lands on-chain.

Who learns what

Section titled “Who learns what”
PartyLearns
SenderThe value
AuditorThe value, by decrypting; guaranteed to match the commitment
Everyone elseA 64-byte ciphertext and a proof; never the value

Real-world uses

Section titled “Real-world uses”
  • Confidential payroll. The tax authority reads every salary from the chain, and the employer can’t under-report one. (use case)
  • Sealed-bid auctions. Each bid is encrypted to the auctioneer with a proof that it’s between the reserve and the deposit, so no bidder can back out by refusing to reveal. (use case)
  • Audited transfers. Every confidential transfer carries the amount for a regulator, enforced by the transfer proof. (use case)

When not to use it

Section titled “When not to use it”
  • No single party should read individual values. Use split trust.
  • The value is a large number. Decryption ends in a search that only works for small values (up to about 2⁴³). Split amounts into 32-bit pieces (limbs) and encrypt each one, as the payroll and points demos do.

Watch out for

Section titled “Watch out for”
  • Verify the auditor’s key. Encrypt only to a key that came with a proof its owner knows the secret (VerifiedKeyShare.verify), or a rogue key could lock the auditor out.
  • Never admit ciphertexts with s -> true unless the ledger already verified that exact statement. The verifier lambda is what makes the guarantee.
  • The auditor can leak. Anyone who can decrypt can also share. Rotate keys, and consider a threshold key for high-value data.
  • Maturity. Experimental. Secret operations are offline/isolated only.
